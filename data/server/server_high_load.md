# 服务器系统负载过高（Load Average / IO 等待）诊断与处理

## 问题现象

`uptime` / `top` 显示 load average 远超 CPU 核心数；系统整体卡顿、命令响应慢，但 CPU 使用率（us）不一定高；常伴随磁盘繁忙、iowait（wa）偏高。

**与"CPU 飙高"的区别**：负载高未必是算力打满，更多是进程在等 IO 或被阻塞——所以排查方向不同。

## 排查步骤

### 1. 看负载与其构成

```bash
uptime                  # 1/5/15 分钟负载，超过核心数即过载
nproc                   # CPU 核心数，用于对比
top                     # 关注 load average 与 %wa（IO 等待）
vmstat 2 5              # r=可运行队列, b=不可中断阻塞, wa=IO 等待
```

**判断方向**：`r` 大 → 在等 CPU；`b` 大 / `wa` 高 → 在等 IO（磁盘 / 网络）。

### 2. 定位 IO 瓶颈

```bash
iostat -x 2 5           # %util 接近 100% 的磁盘即瓶颈；await 高=单次 IO 慢
iotop -o                # 实时看哪个进程在狂读写
pidstat -d 2            # 各进程 IO 量
```

### 3. 找不可中断（D 状态）进程

```bash
ps -eo state,pid,cmd | grep "^D"   # D 状态进程通常卡在 IO（磁盘 / NFS）
```

## 常见原因

- **磁盘 IO 瓶颈**：慢盘 / RAID 降级 / 大量随机读写 / 日志狂刷。
- **数据库大查询或全表扫描**导致磁盘繁忙。
- **内存不足触发频繁 swap**（swap in/out 高，伪装成 IO 负载）。
- **NFS / 网络存储卡顿**，进程陷入 D 状态。
- **进程数爆炸**（fork 风暴）导致可运行队列堆积。

## 解决方案

### 临时止血

```bash
iotop -o                       # 锁定高 IO 进程
ionice -c3 -p <PID>            # 降低其 IO 优先级
free -h                        # swap 导致的，处理占内存大户
```

### 根本修复

- IO 密集：换 SSD、拆分读写、加缓存层、限制日志写入频率。
- 数据库：优化慢查询、加索引、读写分离（参考慢查询文档）。
- 内存不足：扩内存 / 修内存泄漏，减少 swap 依赖。
- 网络存储：排查 NFS 服务端、加超时重试、热数据本地化。

## 预防措施

- 同时监控 **load、%wa、iostat %util**，而非只看 CPU。
- 建立 IO 基线，磁盘 %util 持续 >80% 告警。
- 容量规划，避免单盘承载过多随机 IO。
