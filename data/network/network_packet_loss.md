# 网络丢包与高延迟诊断与处理

## 问题现象

服务间歇性超时、请求时快时慢、连接偶发中断；`ping` 有丢包或延迟抖动大；下载 / 传输速度不稳定。

**与"DNS 解析失败"的区别**：能连上、能解析，但**网络质量差、时通时断**，而不是完全连不上。

## 排查步骤

### 1. 确认丢包与延迟

```bash
ping -c 100 目标IP            # 看 packet loss% 和 rtt 抖动
mtr 目标IP                    # 逐跳丢包 / 延迟，定位是哪一跳出问题（最有用）
traceroute 目标IP             # 路由路径
```

### 2. 看本机网卡与连接质量

```bash
ip -s link                    # 网卡收发包、errors、dropped 是否持续增长
ethtool eth0                  # 速率 / 双工是否协商正确（半双工=灾难）
netstat -s | grep -i retrans  # TCP 重传次数，重传多说明链路质量差
```

### 3. 分段缩小范围（内网 / 公网 / 中间链路）

```bash
ping 网关IP ; ping 同机房IP ; ping 8.8.8.8   # 逐段定位丢包出现在哪一层
```

## 常见原因

- **网卡 / 网线 / 交换机端口故障**，errors、dropped 持续增长。
- **网卡速率 / 双工协商错误**（如协商成 100M 半双工）。
- **带宽打满**：某业务占满出口带宽，其他请求排队、丢包。
- **中间链路抖动**（运营商 / 跨机房专线），mtr 某一跳丢包。
- **防火墙 / 安全设备限速**；`nf_conntrack` 表满丢新连接。

## 解决方案

### 临时止血

- 切换链路 / 网卡，或将流量切到备用节点。
- 限制占满带宽的业务（限速、降级非核心流量）。
- conntrack 满：临时调大 `nf_conntrack_max`。

### 根本修复

- 硬件：更换故障网线 / 网卡 / 端口，固定网卡速率与双工。
- 带宽：扩容出口带宽，QoS 给核心业务保带宽。
- 中间链路：拿 mtr 报告找运营商 / 机房处理丢包的那一跳。
- 内核调优：增大 conntrack、调整 TCP 重传与缓冲参数。

## 预防措施

- 监控网卡 errors / dropped / 重传率 + 链路丢包延迟拨测。
- 带宽使用率告警，核心业务做 QoS。
- 关键链路双线冗余，自动切换。
