# 端口不通 / 连接被拒 / 连接超时诊断与处理

## 问题现象

客户端报 `Connection refused`、`Connection timed out` 或 `No route to host`；服务"连不上"，但服务器本身在运行。

需先区分三种情况：**拒绝**（端口没监听 / 被防火墙 REJECT）、**超时**（被 DROP / 网络不通）、**解析后仍连不上**。

## 排查步骤

### 1. 服务端：端口到底有没有监听

```bash
ss -lntp | grep <端口>        # 端口是否在 LISTEN
# 注意监听地址：只监听 127.0.0.1 → 外部连不上（高频坑），需要 0.0.0.0
```

### 2. 客户端：连通性逐层测

```bash
ping 服务器IP                          # 通不通（ICMP 可能被禁，仅参考）
nc -zv 服务器IP 端口                    # 端口可达性
curl -v http://服务器IP:端口            # 应用层响应
```

- **refused** → 端口没监听 / 防火墙 REJECT。
- **timeout** → 防火墙 DROP / 云安全组没放行 / 网络不通。

### 3. 防火墙与安全组

```bash
iptables -L -n | grep <端口>          # 本机 iptables
firewall-cmd --list-ports             # firewalld
# 云服务器还要在控制台检查"安全组"是否放行该端口
```

## 常见原因

- **服务只监听 127.0.0.1**，未监听 0.0.0.0（外部访问不到）。
- 服务进程没起来 / 崩了 / 端口配错。
- 本机防火墙或**云安全组未放行**端口。
- 中间网络不通（路由、专线、VPC 配置）。
- **连接数打满**（参考"数据库连接耗尽""线程池耗尽"），新连接被拒。

## 解决方案

### 临时止血

```bash
systemctl status <服务> ; ss -lntp | grep <端口>   # 确认服务在跑、端口对
firewall-cmd --add-port=<端口>/tcp                  # 临时放行验证
# 云安全组放行对应端口（控制台操作）
```

### 根本修复

- 改服务监听地址为 `0.0.0.0`（或指定网卡），重启生效。
- 防火墙 / 安全组按最小权限固化放行规则。
- 若因连接数满被拒 → 调大 backlog / 连接上限并排查连接泄漏。

## 预防措施

- 上线检查清单：**监听地址、防火墙、安全组**三者一致放行。
- 端口存活拨测 + 告警。
- 文档化每个服务的端口与放行规则。
